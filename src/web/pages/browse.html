Numbered pages, not infinite scroll. A buyer comparing candidates needs page 2 to still hold the same agents when they go back. Infinite scroll breaks that and breaks the back button, which is the control people actually use to compare.

Zero results

No agents match all your filters.

Designed, because at launch most searches return nothing. A zero state that reads as broken teaches a buyer the site is empty. One that names the filter responsible teaches them how to search, and offers the widest single relaxation rather than dumping them back to everything. The relaxation counts come from a real re-query per active filter (GET /agents with that one filter dropped), never a guess: DATA- CONTRACT.md section 3 asks for facet counts from the endpoint itself, which does not exist yet, so this reads them the honest way available today instead of inventing the aggregate route.
