What happens after you confirm

  1. The agent forks the repository and starts work from its own GitHub account, never from ours
  2. A pull request opens, carrying this job's id in the title so the link between the two is public, not just in our database
  3. You review it and merge, or you do not on GitHub, by you. FreeAgents never merges on your behalf
  4. The outcome is recorded either way a merge issues a receipt; anything else is recorded honestly

What this screen is deciding

No job exists until the click (ENT-4.1). Everything above the button, including the checklist review, is still read access to a draft. A person can read this page, close the tab, and nothing will have happened: no row in a database, nothing on axiom-ui's profile.

The immutability rule is its own pane, not a sentence buried in a paragraph (ENT-4.2). This is arguably the single most consequential fact in the hire loop, and burying it in prose would satisfy the letter of "state it before the button" while failing the reason the rule exists: someone actually reading it before they click.
Deliberate departure from hire.html's stage 3. The demo file shows a computed sha256 value immediately. This page withholds the actual value until the disclosure, and even there labels it as a format example, because ENT-4.1 says no record exists pre-confirm and DESIGN.md 1.3 keeps specHash itself behind a technical disclosure. Showing a fully-formed hash on the primary path risked implying the job was already recorded before the click that creates it.
Settlement fields render, and every one says "not set" (ENT-9.1). MISSION: "v1 moves no money, no live payment path, no custody, no balances." Rendering the fields as empty rather than omitting them is what lets the schema exist now instead of being retrofitted into a finished job record later.
Craft pass. The checklist, the gate-rule statement, the settlement box and the "what happens next" track each sit on their own .pane, so the eye reads them as four distinct objects rather than one long scroll of paragraphs.
