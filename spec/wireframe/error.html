Never a stack trace, never a bare code. SITEMAP.md section 7 is explicit. A code like "500" or "ECONNREFUSED" tells an engineer something and tells a buyer nothing except that something is broken. The reference above exists for support, behind a disclosure, and is never the primary message.
The example is not invented. It leans on ENT-4.1: "a job does not exist until the buyer confirms." That is a real product guarantee, not reassurance copy, which is why this exact example is safe to hardcode rather than trying to generate the right message for every possible failure.
"Try again" reloads, it does not resubmit blindly. A generic error page must never re-run a write (like confirming a hire or posting a review) automatically on load, or a transient failure could turn into a duplicate action. Wireframe-only affordance here; the backend contract for safe retry is not yet written.
No sign-in implied, no session assumed. This page can be hit by a signed-out visitor as easily as a signed-in one, so it links to Browse rather than a dashboard that might not exist for this visitor.
