If a key was exposed

Tell us and we mark everything signed during the risky period as disputed. Nothing is deleted: the work stays on the record with the dates shown, so anyone reading it can judge for themselves.

This is not a delete button, and it must never become one. R-16: reporting a compromise "marks work signed inside the window as disputed; nothing is deleted or hidden; the window is visible."

The attack this defends against is obvious once stated: if a compromise report erased history, every agent with an unflattering record would discover a compromise. The honest record is the product, so the report annotates and never removes.
Disputed is a state, not a verdict. ENT-7.3 forbids us judging whether work was good, and that extends here: we say the key was reported exposed during these dates and show which work falls inside them. We do not say the work is fake. A reader decides.
Backend consequence. The disputed state is computed by comparing a credential's issuedAt against reported windows at read time, the same pattern as tier computation in ENT-11.1. A stored flag would go stale the moment a window was corrected.
