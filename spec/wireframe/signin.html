Two invariants collide here. Invariant 8: "Sign-in is GitHub OAuth or a passkey." Invariant 7: ArcBlock is "visible, never required... Celebrate the rails, never toll them." So the wallet is shown and explained, never the gate. A seed phrase between a buyer and a hire is a closed tab.
No password field anywhere, ever. A marketplace built on verified identity that stores password hashes has added the one attack surface it exists to remove. GitHub OAuth also does double duty: it is the same account the ownership proof is later tested against.

The account-type question is gone. The operator, 2026-08-19: "I don't think we need the choice for hire an agent, list an agent I operate or both. Just an account should be able to do both. That shouldn't even be a question."

Correct, and the previous version argued against itself: its own note said ENT-1 has no role field and should not gain one, then asked the question anyway. A question whose answer changes nothing is pure friction. Every account can hire and can list.
Removing it collapsed the whole signup. With role gone, step 1 held only a display name, which GitHub already gave us. So a three-step wizard became one button. Nothing else was cut to get there: the steps were carrying a question that did not need asking.

Backend consequence: no role column, no capability flag, no branching after auth. An operator hiring another agent is normal, and a schema treating the two as exclusive would have to be unpicked later.

See how the proof works
The form itself lives on provegithub.html (P-19), not here. Changed 2026-08-20. This section used to carry a working copy of the proof control, which meant two screens owned the same action and would drift apart the first time either changed.

SITEMAP.md gives the proof its own page for a reason beyond tidiness: ENT-5 has four states, including the ENT-5.3 demotion where a gist stops resolving. That is not a thing a signup page can represent, and it is not a thing a person meets during signup. The proof is available any time, which is the whole point of it being optional.
The identity is SHOWN, never demanded. Invariant 8: the ownership proof "is one authorization click, with the platform composing the signed statement and publishing the gist through the API. Verification is displayed, never assigned as a task."

The user ticks a box. Behind it the platform composes the statement, signs it, publishes the gist, points the DID document back, and checks both directions. All of that is ENT-5 and none of it is the user's problem.
Optional, deliberately. Someone who skips it gets a working account whose agents can never rise above portfolio claims. The cost is visible on the profile rather than enforced at the door: a wall at signup loses the operator, a visible ceiling converts them later.
